# 实战二：图片与列表页优化

> [返回总目录](../README.md) ｜ [相关服务：ImageService](../01-接口参考/06-图片与字幕/ImageService.md)

列表页是一个客户端的门面：图片多、滚动快、网络差。本文给出一套「少请求、不闪、能缓存」的实现套路。

## 1. 图片 URL 的正确拼法

Emby 的图片接口是独立的二进制端点，不在 JSON 里：

```text
GET /Items/{Id}/Images/{Type}?tag={Tag}&maxHeight={h}&quality={q}
GET /Items/{Id}/Images/{Type}/{Index}?tag={Tag}&maxWidth={w}
```

```javascript
function imageUrl(item, type = 'Primary', { index, maxHeight = 300, maxWidth, quality = 90 } = {}) {
  const tag =
    type === 'Primary' ? item.PrimaryImageTag
    : type === 'Backdrop' ? (item.BackdropImageTags || [])[index ?? 0]
    : (item.ImageTags || {})[type];

  if (!tag) return null;   // 没有图就别拼 URL，直接显示占位图

  const p = new URLSearchParams({ tag, quality: String(quality) });
  if (maxHeight) p.set('maxHeight', String(maxHeight));
  if (maxWidth) p.set('maxWidth', String(maxWidth));

  const idx = (type === 'Backdrop' || index !== undefined) ? `/${index ?? 0}` : '';
  return `${baseUrl}/Items/${item.Id}/Images/${type}${idx}?${p}`;
}
```

三个「必须有」：

| 项 | 原因 |
|---|---|
| `tag` 必带 | 服务端据此判断图片是否变化；不带 tag 会拿到旧缓存或额外 302 |
| `maxHeight` / `maxWidth` 必带 | 让服务端缩放。原图动辄 2000×3000、几 MB，列表页直接拉原图会拖垮滚动 |
| 无 tag 时不拼 URL | `PrimaryImageTag` 为空表示该条目没有主图，拼出来必然 404 |

## 2. 尺寸阶梯：按用途选分辨率

| 用途 | 建议参数 | 典型体积 |
|---|---|---|
| 横向海报墙（手机 2–3 列） | `maxHeight=300` | 10–30 KB |
| 竖向海报（列表 1 列大图） | `maxHeight=450` | 20–50 KB |
| 详情页主图 | `maxHeight=800` | 80–200 KB |
| 背景大图（Banner/详情头图） | `maxWidth=1920&quality=85` | 100–300 KB |
| 演职人员头像 | `maxHeight=120` | 5–15 KB |
| 用户头像 | `maxHeight=200` | 10–30 KB |

> 原则：**列表页永远不要 `maxHeight` 不传**。省略它等于请求原图。

## 3. 防闪烁：宽高比占位

海报加载前后高度不一致会导致列表跳动。用 `PrimaryImageAspectRatio` 先把占位框撑起来：

```javascript
function posterBox(item) {
  const ratio = item.PrimaryImageAspectRatio || 2 / 3;   // 常见 2:3
  return { aspectRatio: String(ratio), width: '100%' };
}
```

```html
<div class="poster" style="aspect-ratio: 2/3; background:#1c1c1e">
  <img src="..." loading="lazy" onerror="this.remove()" />
</div>
```

| 字段 | 含义 |
|---|---|
| `PrimaryImageAspectRatio` | 主图宽高比（宽/高），常见 `0.6667`（海报）或 `1.7778`（横图） |
| `PrimaryImageTag` | 是否有主图 |
| `BackdropImageTags` | 背景图数组，`[0]` 是详情页头图首选 |

## 4. 惰性加载与预取

```javascript
const io = new IntersectionObserver((entries) => {
  for (const e of entries) {
    if (!e.isIntersecting) continue;
    const img = e.target;
    img.src = img.dataset.src;       // 进入视口才真正下载
    io.unobserve(img);
  }
}, { rootMargin: '200px 0px' });     // 提前 200px 预取，滚动更顺
```

预取策略：

| 场景 | 做法 |
|---|---|
| 竖向滚动列表 | 提前 200–400px 触发 |
| 横向轮播（继续观看） | 当前页 + 下一页各预取 3 张 |
| 详情页 | 进入页面时并行预取海报 + 背景图 |

## 5. 缓存：tag 就是版本号

`tag` 变化意味着图片变了，因此可以给图片设置**长缓存**：

```javascript
// 伪代码：把缓存策略与 tag 绑定
cacheControl = "public, max-age=31536000, immutable";   // tag 参与 URL，天然可长期缓存
```

| 策略 | 说明 |
|---|---|
| 内存 LRU | 列表页保留最近 30–50 张，避免来回滚动重复解码 |
| 磁盘缓存 | 键用 `Id + Type + Index + tag + 尺寸`，tag 变了自动失效 |
| 不缓存 404 | 无图条目用占位图，不要反复重试 |

> 换了封面但客户端显示旧图，99% 是 URL 没带 `tag`（或带了但被 CDN 忽略）。

## 6. 列表接口的减负

`BaseItemDto` 字段极多，默认返回的是「精简版」；但 `Fields` 一旦多要，体积会成倍增长。列表页与详情页要分开取：

```javascript
// ✅ 列表页：只要排版必需的三件
const listQuery = {
  ParentId: viewId, Recursive: 'true', IncludeItemTypes: 'Movie',
  SortBy: 'SortName', SortOrder: 'Ascending', StartIndex: 0, Limit: 24,
  Fields: 'PrimaryImageAspectRatio',
};

// ❌ 列表页不要带这些：MediaSources、MediaStreams、People、Overview、Chapters
```

| 字段 | 能否进列表页 | 说明 |
|---|---|---|
| `PrimaryImageAspectRatio` | ✅ | 排版必需 |
| `ProductionYear`、`CommunityRating` | ✅ | 卡片副标题 |
| `UserData` | ✅（默认已带） | 已看/进度角标 |
| `Overview` | ❌ | 简介动辄上千字 |
| `MediaStreams` | ❌ | 每条 10+ 轨，体积翻数倍 |
| `People` | ❌ | 演职人员列表，详情页才要 |
| `MediaSources` | ❌ | 播放前才需要 |

## 7. 分页策略

| 策略 | 适用 | 说明 |
|---|---|---|
| 页式（`Limit=24`，滚动加载） | 竖向海报墙 | 每次追加一页，`TotalRecordCount` 算总页数 |
| 窗口式（固定 60 条） | 横向轮播 | 只保留可视窗口附近的数据 |
| 全量 + 本地过滤 | 小库（<200 条） | 一次取完，搜索/筛选在本地做，体验最好 |

```javascript
let start = 0;
async function nextPage(viewId) {
  const { items, total } = await loadList(viewId, { start, limit: 24 });
  start += items.length;
  return { items, hasMore: start < total };
}
```

> 深分页（`StartIndex` 很大）在超大媒体库上会变慢，此时优先用**筛选条件**（年份、类型、标签）缩小集合，而不是一直往后翻。

## 8. 图片接口的隐藏技巧

| 需求 | 做法 |
|---|---|
| 只想知道有没有图，不想下载 | `HEAD /Items/{Id}/Images/{Type}`，看 200/404 |
| 要「看过多少」的角标图 | `GET /Items/{Id}/Images/{Type}/{Index}/{Tag}/{Format}/{MaxWidth}/{MaxHeight}/{PercentPlayed}/{UnPlayedCount}`，服务端直接画进度角标 |
| 要背景图轮播 | `BackdropImageTags` 数组按下标逐个取 `/Images/Backdrop/{i}` |
| 要剧集缩略图 | 分集用 `Primary`，`Thumb` 通常是横向剧照 |
| 用户头像 | `/Users/{UserId}/Images/Primary?tag={UserPrimaryImageTag}` |
| 演职人员头像 | `/Persons/{Name}/Images/Primary`（注意是 Name 不是 Id） |

> `/Persons/{Name}/Images/...` 用的是**人物名称**且需 URL 编码，这是 Emby 图片接口里唯一按名字取图的地方之一（另一个是 `/Genres/{Name}`、`/Studios/{Name}`）。

## 9. 一次列表请求的完整示例

```javascript
async function renderRow(viewId) {
  const q = await api(`/Users/${state.userId}/Items`, {
    query: {
      ParentId: viewId, Recursive: 'true', IncludeItemTypes: 'Movie,Series',
      SortBy: 'DateCreated', SortOrder: 'Descending', Limit: 20,
      Fields: 'PrimaryImageAspectRatio,ProductionYear,CommunityRating',
    },
  });

  return q.Items.map(it => ({
    title: it.Name,
    year: it.ProductionYear,
    rating: it.CommunityRating,
    played: it.UserData?.Played ?? false,
    progress: (it.UserData?.PlaybackPositionTicks ?? 0) / (it.RunTimeTicks || 1),
    poster: imageUrl(it, 'Primary', { maxHeight: 300 }),   // 无图返回 null
    backdrop: it.BackdropImageTags?.length
      ? imageUrl(it, 'Backdrop', { index: 0, maxWidth: 1920 })
      : null,
  }));
}
```

## 10. 优化效果自查清单

| 检查项 | 达标标准 |
|---|---|
| 列表页请求体积 | 单页 24 条 < 100 KB |
| 单张海报 | < 40 KB，且带 `maxHeight` |
| 滚动是否抖动 | 有宽高比占位，无跳动 |
| 图片是否重复下载 | 有 LRU/磁盘缓存，键含 `tag` |
| 无图条目 | 显示占位图，不产生 404 请求 |
| 首屏时间 | 先渲染文字骨架，图片异步补齐 |
| 详情页 | 才请求 `MediaStreams`/`People`/`Overview` |

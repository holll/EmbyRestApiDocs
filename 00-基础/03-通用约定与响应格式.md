# 通用约定与响应格式

> [返回总目录](../README.md) ｜ [上一篇：认证与鉴权](02-认证与鉴权.md) ｜ [下一篇：错误与排查](04-错误与排查.md)

Emby 的 REST API 风格高度统一：路径是名词，动作用 HTTP 方法表达，列表用 `QueryResult` 包一层，时间用 tick。把这些约定记熟，看单个接口文档就很快。

## 1. 基础约定

| 项目 | 约定 |
|---|---|
| 基础地址 | `http://<host>:8096`（HTTPS 默认 `8920`） |
| 路径前缀 | 全部以 `/` 开头，无统一版本前缀（`/Users`、`/Items`、`/Sessions`…） |
| 请求体 | `Content-Type: application/json`，字段名 PascalCase（如 `ItemId`、`PositionTicks`） |
| 响应体 | JSON，字段名同样是 PascalCase；几乎所有字段大小写敏感 |
| 字符编码 | UTF-8，中文直接用 JSON 转义或原文均可 |
| 布尔值 | JSON `true` / `false`；查询参数用字符串 `true` / `false` |
| 数组在查询参数里 | 用英文逗号分隔：`IncludeItemTypes=Movie,Series` |
| 日期时间 | ISO 8601，如 `2024-05-01T12:00:00.0000000Z` |
| 时长/位置 | **tick**（100 纳秒），见下文 |

## 2. 时间单位：tick

这是接入 Emby 最容易踩的坑。所有 `*Ticks` 字段（`RunTimeTicks`、`PositionTicks`、`StartTimeTicks`、`SeekPositionTicks`…）单位都是 **tick**。

```text
1 秒   = 10,000,000 ticks
1 毫秒 = 10,000 ticks
1 分钟 = 600,000,000 ticks
1 小时 = 36,000,000,000 ticks
```

换算：

```javascript
const TICKS_PER_SECOND = 1e7;
const ticksToSeconds = t => t / TICKS_PER_SECOND;            // 12345678 → 1.2345678 秒
const secondsToTicks = s => Math.round(s * TICKS_PER_SECOND); // 90 秒 → 900000000
```

```python
TICKS_PER_SECOND = 10_000_000
def ticks_to_seconds(t): return t / TICKS_PER_SECOND
def seconds_to_ticks(s): return int(s * TICKS_PER_SECOND)
```

> 前端存进度时建议**内部统一用秒**，只在请求/响应边界做转换，避免满屏 `10000000`。

## 3. 分页与列表：QueryResult

所有返回列表的接口都套一层 `QueryResult<T>`：

```json
{
  "Items": [ { "Id": "…", "Name": "…" }, { "Id": "…", "Name": "…" } ],
  "TotalRecordCount": 1287,
  "StartIndex": 0
}
```

| 字段 | 含义 |
|---|---|
| `Items` | 当前页数据 |
| `TotalRecordCount` | 满足条件的**总数**（可用来算总页数） |
| `StartIndex` | 本次请求的起始偏移，回显便于校验 |

分页参数是所有列表接口通用的两个：

| 参数 | 说明 |
|---|---|
| `StartIndex` | 从第几条开始，默认 `0` |
| `Limit` | 本页最多返回多少条；不传则由服务端默认（通常较大） |

```text
总页数 = ceil(TotalRecordCount / Limit)
请求第 n 页（从 0 开始）：StartIndex = n * Limit，Limit 不变
```

> 需要注意：`TotalRecordCount` 只有在**第一次**查询时最准；Emby 对后续分页可能返回近似值，不应据此做严格断言。

## 4. 详情字段的白名单：Fields

`BaseItemDto` 有上百个字段，但列表接口**默认只返回精简版**（无 `MediaStreams`、`People`、`ProviderIds` 等重字段）。需要时通过 `Fields` 显式索取：

```text
GET /Users/{UserId}/Items?ParentId=…&Fields=MediaSources,MediaStreams,People,Overview,ProviderIds,Path,Taglines,Studios,Genres
```

常见可选值：

| Fields 值 | 用途 |
|---|---|
| `MediaSources` | 媒体源（含直链、容器、码率）——播放前必备 |
| `MediaStreams` | 音视频/字幕轨信息——做音轨字幕选择必备 |
| `People` | 演职人员（含头像 ID） |
| `Overview` | 简介（较长，列表页慎用） |
| `ProviderIds` | 外部 ID（Imdb/Tmdb/Tvdb）——跳转豆瓣等外部站点用 |
| `Path` | 服务器上的物理路径（仅管理员可见才返回） |
| `Genres` / `Studios` / `Taglines` | 分类、制片方、宣传语 |
| `DateCreated` | 入库时间——「最近添加」排序常用 |
| `PrimaryImageAspectRatio` | 主图宽高比——排版防抖必备 |

> 经验：**列表页只取 3–5 个轻字段，详情页再补齐**。一次性要全部字段会让响应体从几十 KB 涨到几 MB，移动端尤其明显。

## 5. 图片 URL 规则

图片不走 JSON，而是独立的二进制接口，格式统一：

```text
GET /Items/{ItemId}/Images/{Type}?tag={Tag}&maxHeight={h}&quality={q}
```

| 段 | 取值 |
|---|---|
| `Type` | `Primary`（海报）、`Backdrop`（背景图，可加 `/{Index}`）、`Logo`（Logo）、`Thumb`（缩略图）、`Banner`、`Art`、`Disc`、`BoxRear`、`Menu` |
| `tag` | **必带**，取自 DTO 的 `ImageTags.Primary` / `BackdropImageTags[i]`，用于缓存失效 |
| `maxHeight` / `maxWidth` | 请求服务端缩放，避免下载原图 |
| `quality` | JPEG 质量 `0–100`，默认 90 |
| `index` | 背景图序号，`Backdrop/0`、`Backdrop/1`… |

```text
海报： /Items/8f2c.../Images/Primary?tag=3a7f...&maxHeight=300&quality=90
背景： /Items/8f2c.../Images/Backdrop/0?tag=9c2e...&maxWidth=1920
用户头像：/Users/{UserId}/Images/Primary?tag=...&maxHeight=200
```

三个判断技巧：

1. `PrimaryImageTag` 为空 → 该条目没有主图，客户端应显示占位图，而不是拼一个必然 404 的 URL；
2. `ImageTags` 是「类型 → tag」的字典，`BackdropImageTags` 是数组（顺序即 index）；
3. `tag` 变化意味着图片变了，客户端可以放心长缓存（`Cache-Control` 自己控制）。

## 6. HTTP 方法与语义

| 方法 | 语义 | 例子 |
|---|---|---|
| `GET` | 查询，**不得有副作用** | `GET /Items/{Id}`、`GET /Users` |
| `POST` | 创建 **或** 更新 **或** 执行动作 | `POST /Users/New`、`POST /Items/{Id}/Refresh`、`POST /Sessions/Playing` |
| `DELETE` | 删除/取消 | `DELETE /Users/{Id}`、`DELETE /Users/{UserId}/PlayedItems/{Id}` |

几个反直觉的 Emby 习惯，写代码前务必知道：

- **更新已有对象通常用 `POST` 到同一个路径**，例如 `POST /Users/{Id}` 更新用户（不是 `PUT`）。
- 很多「动作类」接口是 `POST + 空 body`，例如 `POST /Items/{Id}/Refresh`、`POST /ScheduledTasks/Running/{Id}`。
- 同一动作常有两个路径：`DELETE /Users/{UserId}/PlayedItems/{Id}` 与 `POST /Users/{UserId}/PlayedItems/{Id}/Delete` 等价。**优先用语义正确的那个**。

## 7. 媒体对象：BaseItemDto

列表、详情、搜索结果里的每个条目都是 `BaseItemDto`。高频字段（完整定义见 [BaseItemDto](../02-数据模型/02-媒体条目.md)）：

| 字段 | 含义 |
|---|---|
| `Id` | 条目 ID（32 位 hex） |
| `Name` | 显示名称 |
| `Type` | `Movie` / `Series` / `Season` / `Episode` / `Audio` / `Photo` / `BoxSet` / `Folder` / `Person` … |
| `MediaType` | `Video` / `Audio` / `Photo` / `Book` |
| `CollectionType` | 仅视图有：`movies` / `tvshows` / `music` / `books` / `photos` / `boxsets` |
| `ParentId` / `SeriesId` / `SeasonId` | 层级关系 |
| `IndexNumber` / `ParentIndexNumber` | 集数 / 季数 |
| `RunTimeTicks` | 时长（tick） |
| `UserData` | 该用户的播放状态（`Played`、`PlaybackPositionTicks`、`PlayCount`、`IsFavorite`） |
| `ImageTags` / `BackdropImageTags` | 图片标记 |
| `ProviderIds` | 外部 ID 字典 |
| `IsFolder` | 是否容器（需要继续向下钻取） |

> 层级建议：`Views(CollectionType)` → `Series` → `Season` → `Episode`；电影库是 `Movie` 直接到条目，音乐库是 `MusicAlbum` → `Audio`。

## 8. 常见查询参数速查

几乎所有列表接口都支持下面这些（详见 [Items 服务](../01-接口参考/02-媒体库浏览/ItemsService.md)）：

| 参数 | 说明 |
|---|---|
| `ParentId` | 限定在某个条目/文件夹下查询 |
| `Recursive` | 是否递归子文件夹 |
| `IncludeItemTypes` / `ExcludeItemTypes` | 按类型过滤（逗号分隔） |
| `SortBy` | 排序字段：`SortName`、`DateCreated`、`PremiereDate`、`CommunityRating`、`Random` |
| `SortOrder` | `Ascending` / `Descending` |
| `SearchTerm` | 关键词搜索 |
| `Filters` | `IsUnplayed`、`IsPlayed`、`IsFavorite`、`IsResumable` 等 |
| `IsFavorite` / `IsPlayed` | 布尔过滤 |
| `MinCommunityRating` / `MinOfficialRating` | 评分/分级过滤 |
| `Years` / `Genres` / `Studios` / `PersonIds` / `Tags` | 年份、类型、制片方、人物、标签过滤 |
| `StartIndex` / `Limit` | 分页 |
| `Fields` | 补充返回字段 |

## 9. 一个标准请求的完整形态

```http
GET /Users/8f2c1d3e4a5b6c7d8e9f0a1b2c3d4e5f/Items?ParentId=7a1b&Recursive=true&IncludeItemTypes=Movie&SortBy=DateCreated&SortOrder=Descending&StartIndex=0&Limit=24&Fields=PrimaryImageAspectRatio,ProductionYear HTTP/1.1
Host: 192.168.1.10:8096
X-Emby-Authorization: Emby UserId="8f2c1d3e4a5b6c7d8e9f0a1b2c3d4e5f", Client="MyApp", Device="PC", DeviceId="abcd-1234", Version="1.0.0", Token="b7d3f0c9a1e24f6d8b0c5a7e9f1d3b2c"
Accept: application/json
```

响应：

```json
{
  "Items": [
    {
      "Id": "c9e1...",
      "Name": "沙丘2",
      "Type": "Movie",
      "ProductionYear": 2024,
      "RunTimeTicks": 99600000000,
      "PrimaryImageTag": "3a7f...",
      "UserData": { "Played": false, "PlaybackPositionTicks": 0, "PlayCount": 0 }
    }
  ],
  "TotalRecordCount": 342,
  "StartIndex": 0
}
```

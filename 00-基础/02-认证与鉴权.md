# 认证与鉴权

> [返回总目录](../README.md) ｜ [上一篇：快速开始](01-快速开始.md) ｜ [下一篇：通用约定与响应格式](03-通用约定与响应格式.md)

Emby 的认证体系只有两条主线：**用户令牌（AccessToken）** 和 **API 密钥（API Key）**。搞清楚这两者，以及请求头怎么带，就解决了 90% 的接入问题。

## 1. 客户端身份头：X-Emby-Authorization

无论是否已登录，Emby 都要求请求带上客户端身份信息。它有两个名字，内容格式完全一样：

```text
Emby UserId="<用户ID>", Client="<客户端名>", Device="<设备名>", DeviceId="<设备唯一ID>", Version="<版本号>", Token="<令牌>"
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `Client` | 是 | 客户端名称，如 `Emby for Android`。服务端日志和设备列表里显示的就是它 |
| `Device` | 是 | 设备名称，如 `Pixel 7`、`Windows PC` |
| `DeviceId` | 是 | **设备唯一标识，必须自己生成并持久化**。服务端用它区分设备、做远程控制和播放限制 |
| `Version` | 是 | 客户端版本号，纯展示用 |
| `UserId` | 否 | 已登录用户的 ID；未登录时留空 |
| `Token` | 否 | 已登录时的 AccessToken；登录请求本身不带 |

请求头名称两种都接受：

```http
X-Emby-Authorization: Emby Client="MyApp", Device="PC", DeviceId="abcd-1234", Version="1.0.0"
Authorization: Emby Client="MyApp", Device="PC", DeviceId="abcd-1234", Version="1.0.0"
```

> `DeviceId` 为什么重要：Emby 的「设备管理」「远程控制」「播放次数限制」都以 DeviceId 为单位。每次启动随机生成会让服务端把你的客户端当成新设备，设备列表越来越长，远程控制也会失效。

## 2. 用户登录：AuthenticateByName

```http
POST /Users/AuthenticateByName
Content-Type: application/json
X-Emby-Authorization: Emby Client="MyApp", Device="PC", DeviceId="abcd-1234", Version="1.0.0"

{ "Username": "demo", "Pw": "123456" }
```

请求体字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `Username` | string | 是 | 用户名（也接受邮箱形式的 Connect 用户名） |
| `Pw` | string | 是 | 密码。部分版本也接受 `Password` 字段，建议统一用 `Pw` |

成功响应：

```json
{
  "User": {
    "Id": "8f2c1d3e4a5b6c7d8e9f0a1b2c3d4e5f",
    "Name": "demo",
    "ServerId": "a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6",
    "Policy": { "IsAdministrator": false, "EnableAllFolders": true }
  },
  "SessionInfo": { "Id": "e5b1c7d9...", "DeviceName": "PC", "Client": "MyApp" },
  "AccessToken": "b7d3f0c9a1e24f6d8b0c5a7e9f1d3b2c",
  "ServerId": "a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6"
}
```

**要保存的四个值**：`AccessToken`、`User.Id`、`SessionInfo.Id`、`ServerId`。

失败时返回：

| 状态码 | 含义 | 典型原因 |
|---|---|---|
| `401` | 用户名或密码错误 | 密码错、用户被禁用 |
| `400` | 请求不合法 | 缺少 `X-Emby-Authorization` 头、body 不是 JSON |

## 3. 令牌的三种传递方式

| 方式 | 写法 | 评价 |
|---|---|---|
| 专用头 | `X-Emby-Token: <AccessToken>` | **推荐**，简单且不进日志 |
| 授权头 | `X-Emby-Authorization: Emby ..., Token="<AccessToken>"` | 推荐，与身份信息一并传递 |
| 查询参数 | `?api_key=<AccessToken>` | 兼容用，令牌会落到访问日志/代理日志，**不要用于新项目** |

一个完整请求的样子：

```bash
curl "http://192.168.1.10:8096/Users/8f2c1d3e.../Items/Resume" \
  -H 'X-Emby-Authorization: Emby UserId="8f2c1d3e...", Client="MyApp", Device="PC", DeviceId="abcd-1234", Version="1.0.0", Token="b7d3f0c9..."'
```

## 4. 管理员 API Key

除了用户令牌，Emby 还支持「API 密钥」——由管理员在控制台生成，**不受用户权限约束**，常用于自动化脚本、Webhook、监控。

```bash
# 用用户令牌创建（需管理员）
curl -X POST "http://192.168.1.10:8096/Auth/Keys?App=backup-script" \
  -H "X-Emby-Token: <管理员令牌>"
```

```bash
# 用 API Key 直接访问
curl "http://192.168.1.10:8096/System/Info" -H "X-Emby-Token: <API Key>"
```

```bash
# 列出 / 删除
GET    /Auth/Keys
DELETE /Auth/Keys/{Key}
```

| 对比项 | 用户令牌 AccessToken | API Key |
|---|---|---|
| 来源 | 登录接口签发 | 管理员在控制台/接口生成 |
| 权限 | 受该用户 Policy 限制 | 等同管理员 |
| 生命周期 | 随会话，可在设备管理中失效 | 手动删除才失效 |
| 适用场景 | 客户端 App | 服务端脚本、Webhook、监控 |

## 5. 权限模型：UserPolicy

登录响应里的 `User.Policy` 决定这个账号能做什么。对接客户端时至少要读这几个字段：

| 字段 | 含义 | 客户端应如何处理 |
|---|---|---|
| `IsAdministrator` | 是否管理员 | 决定是否显示「服务器设置」入口 |
| `IsDisabled` | 是否被禁用 | 禁用用户登录会失败 |
| `EnableAllFolders` | 是否有权访问全部媒体库 | 为 `false` 时按 `EnabledFolders` 过滤视图 |
| `EnabledFolders` | 允许访问的媒体库 ID 列表 | 与 `/Users/{UserId}/Views` 结果取交集 |
| `EnableContentDownloading` | 是否允许下载 | 控制下载按钮 |
| `EnableRemoteControlOfOtherUsers` | 是否允许控制他人设备 | 控制远程控制面板 |
| `EnablePlaybackRemuxing` / `EnableVideoPlaybackTranscoding` | 是否允许转码 | 不允许时只能直连播放 |
| `BlockedTags` / `AllowedTags` | 标签级内容限制 | 儿童账号常用 |
| `MaxParentalRating` | 最高可看分级 | 列表过滤时剔除超限内容 |

> 提示：`/Users/{UserId}/Views` 返回的视图**本身已经按权限过滤过**，大多数情况下直接用它的结果即可，不必自己再算 `EnabledFolders`。

## 6. 令牌失效与登出

Emby 没有专门的「登出」接口。客户端登出＝丢弃本地保存的 `AccessToken`。

要让令牌在服务端失效，可以：

```bash
# 删除设备（管理员），该设备的会话与令牌随之失效
DELETE /Devices?Id=<DeviceId>

# 删除 API Key
DELETE /Auth/Keys/{Key}
```

## 7. 忘记密码（可选功能）

Emby 允许本地用户通过 PIN 重置密码，前提是管理员在服务器上配置了密码重置方式：

```text
POST /Users/ForgotPassword                    发起流程（body: { "UserName": "demo" }）
POST /Users/ForgotPassword/Pin               校验 PIN（body: { "Pin": "1234" }）
```

具体可用性取决于服务器配置，第三方客户端只需在登录页提供入口并处理 400/404。

## 8. Emby Connect（云账号，可选）

用户用邮箱注册 Emby Connect 后，无需知道服务器地址即可登录。流程与本地登录不同：

```text
1. POST /Connect/Exchange        用 Connect 的 UserId + 服务器 Id 换取本地访问令牌
2. GET  /Connect/Users           查询 Connect 账号关联的服务器
3. POST /Connect/Link            建立/解除用户与 Connect 的绑定（管理端）
```

对多数第三方客户端而言，**优先实现本地登录**（`AuthenticateByName`）即可；Connect 作为增强项，等主流程跑通再补。

## 9. 鉴权问题排查表

| 现象 | 原因 | 处理 |
|---|---|---|
| 登录 400 且提示 Client 信息 | 缺少 `X-Emby-Authorization` 头或 `Client`/`Device`/`DeviceId` 为空 | 补齐三个必填字段 |
| 登录 401 | 密码错误、用户被禁用、用户名大小写不符 | 提示用户；管理员可在 `/Users` 查看 `IsDisabled` |
| 任意接口 401 | 令牌为空、过期、或用了别的服务器的令牌 | 重新登录；确认 `ServerId` 一致 |
| 任意接口 403 | 令牌有效但无权限（如普通用户调管理员接口） | 检查 `Policy`，或改用管理员/API Key |
| 部分接口 200 但数据为空 | 用户 Policy 限制（文件夹/分级/标签） | 用 `/Users/{UserId}/Views` 判断可见范围 |
| 设备列表出现大量陌生条目 | 每次启动都重新生成 `DeviceId` | 持久化 DeviceId，跨启动复用 |

# 错误处理与排查

> [返回总目录](../README.md) ｜ [上一篇：通用约定与响应格式](03-通用约定与响应格式.md) ｜ [下一篇：常用接口速查表](05-常用接口速查表.md)

Emby 的错误信息偏「安静」：多数失败只给一个状态码，响应体常常是空的或一句 `Unauthorized`。所以排查要靠**状态码 + 请求上下文**，而不是指望错误文案。

## 1. 状态码总表

| 状态码 | 含义 | 典型触发场景 | 处理建议 |
|---|---|---|---|
| `200` | 成功 | 绝大多数请求 | — |
| `204` | 成功且无内容 | 部分 `DELETE`/`POST` 动作接口 | 视为成功 |
| `302` | 重定向 | 登录后跳转、`/web` 页面 | 客户端 API 调用一般不跟随，按需处理 |
| `400` | 请求不合法 | 缺必填参数、body 不是 JSON、路径参数格式错 | 检查请求构造，**不要重试** |
| `401` | 未认证 | 令牌缺失/失效、登录密码错、身份头缺失 | 重新登录；登录接口本身见下节 |
| `403` | 已认证但无权限 | 普通用户调管理员接口、Policy 禁止该操作 | 降级 UI 或提示无权限，不要重试 |
| `404` | 资源不存在 | 条目 ID 错、图片无 tag、服务端未启用该功能 | 检查 ID 与功能开关 |
| `500` | 服务器内部错误 | 服务端异常、数据库/插件问题 | 可有限重试（1 次），并提示查看服务器日志 |
| `502` / `504` | 网关错误/超时 | 反向代理后面的 Emby | 检查代理超时设置（长请求易 504） |

## 2. 认证类错误怎么定位

`401` 是最常见的错误，按顺序排查：

| 检查项 | 说明 |
|---|---|
| 令牌是否为空 | 未登录就调了需要权限的接口 |
| 令牌是否属于当前服务器 | 用 A 服务器的令牌请求 B 服务器必然 401 |
| 请求头名称是否正确 | `X-Emby-Token` 或 `X-Emby-Authorization`，不要写成 `Authorization: Bearer …` |
| 是否用了 `?api_key=` | 可用，但某些反代会剥离查询串，优先改用头 |
| 登录接口 401 | 用户名/密码错，或被禁用（`Policy.IsDisabled = true`） |
| 登录接口 400 | 缺 `X-Emby-Authorization` 头，或 `Client`/`Device`/`DeviceId` 为空 |

> 判断令牌是否还有效：`GET /Users/{UserId}` 会返回当前用户信息；401 即失效。

## 3. 播放类问题排查

### 3.1 PlaybackInfo 返回空 / 无法播放

| 现象 | 原因 | 处理 |
|---|---|---|
| `MediaSources` 为空 | 条目没有可用媒体文件（仅元数据）、或文件被移走 | 检查条目 `Path`、用 `POST /Items/{Id}/Refresh` 重扫 |
| 有 `MediaSources` 但无 `DirectStreamUrl` | 需要转码，但用户 Policy 禁止转码 | 检查 `EnableVideoPlaybackTranscoding` |
| 播放地址 404 | 拼 URL 时少/多了斜杠、用了错误端口 | `DirectStreamUrl`/`TranscodingUrl` 已是相对路径，拼 `scheme://host:port` 即可 |
| 播放立刻中断 | 缺少 `X-Emby-Token`，媒体流也需要鉴权 | 播放请求同样要带令牌（或 `api_key`） |
| 一直缓冲 | 带宽不足、`MaxStreamingBitrate` 设得过高 | 降低 `MaxStreamingBitrate`，或在 DeviceProfile 里声明受限能力 |

### 3.2 进度不保存

| 现象 | 原因 | 处理 |
|---|---|---|
| 「继续观看」里没有该条目 | 从未调 `Sessions/Playing/Progress`，或 `PositionTicks` 一直为 0 | 播放中每 10 秒上报一次；`PositionTicks` 必须递增 |
| 进度回退到 0 | `Stopped` 上报时 `PositionTicks` 传了 0 | 停止时传最终位置 |
| 服务端显示「正在播放」永远不消失 | 没有调 `Sessions/Playing/Stopped` | 退出播放器时务必上报停止 |
| 多端进度不同步 | 不同设备用了不同 `PlaySessionId` | `PlaySessionId` 从 PlaybackInfo 响应里取，整场复用 |

### 3.3 图片问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 404 | `tag` 为空、或该条目无此类型图片 | 先判断 `ImageTags`/`PrimaryImageTag` 是否有值 |
| 图片模糊 | 没传 `maxHeight`，服务端按原图返回后被客户端压小 | 传合适 `maxHeight`，让服务端缩放 |
| 换了封面但显示旧图 | 缓存键没带 `tag` | URL 必须带 `tag`，tag 变了才会刷新 |

## 4. 权限与可见性

`403` 与「返回成功但没有数据」是权限问题的两种表现：

| 场景 | 判断方法 |
|---|---|
| 某媒体库不显示 | `Policy.EnableAllFolders=false`，检查 `EnabledFolders` 是否包含该库 ID |
| 某条目列表为空但服务端有 | 分级限制（`MaxParentalRating`）、标签限制（`BlockedTags`） |
| 管理员接口 403 | 当前令牌不是管理员，用 `/Users/{UserId}` 看 `Policy.IsAdministrator` |
| 能看列表但不能播 | `EnableContentDownloading` / 转码权限被关；或该条目只能是「仅元数据」 |

## 5. 远程控制不生效

| 现象 | 原因 |
|---|---|
| `/Sessions` 里看不到目标设备 | 目标设备已退出、或 `DeviceId` 每次都在变 |
| 发送 `PlayPause` 无反应 | 目标会话 `SupportsRemoteControl=false`，或 `SupportedCommands` 不含该命令 |
| 只能控制自己的设备 | 需要 `Policy.EnableRemoteControlOfOtherUsers=true` 才能控制他人会话 |
| 控制指令 200 但设备不动 | 命令名必须是 `SupportedCommands` 里的原值（如 `PlayPause`、`Pause`、`Unpause`、`Stop`、`Seek`、`VolumeUp`），拼错也不报错；或会话已过期 |

> 正确做法：先 `GET /Sessions` 读目标会话的 `SupportedCommands`，只渲染它支持的命令。

## 6. 错误处理代码示例

```javascript
async function call(path, { token, deviceInfo, method = 'GET', body } = {}) {
  const headers = {
    'X-Emby-Authorization': `Emby UserId="${deviceInfo.userId || ''}", Client="${deviceInfo.client}", Device="${deviceInfo.device}", DeviceId="${deviceInfo.deviceId}", Version="${deviceInfo.version}"`,
    'Accept': 'application/json',
  };
  if (token) headers['X-Emby-Token'] = token;
  if (body) headers['Content-Type'] = 'application/json';

  const res = await fetch(`${deviceInfo.baseUrl}${path}`, {
    method, headers, body: body ? JSON.stringify(body) : undefined,
  });

  if (res.ok) {
    const text = await res.text();
    return text ? JSON.parse(text) : null;
  }

  switch (res.status) {
    case 400: throw new ApiError('请求参数不合法', 400, false);
    case 401: throw new ApiError('登录已失效，请重新登录', 401, false);
    case 403: throw new ApiError('当前账号无权限执行该操作', 403, false);
    case 404: throw new ApiError('资源不存在', 404, false);
    case 500:
    case 502:
    case 504: throw new ApiError('服务器错误，请稍后重试', res.status, true);
    default:  throw new ApiError(`请求失败（HTTP ${res.status}）`, res.status, false);
  }
}
```

```python
import urllib.request, urllib.error, json

def call(base, path, token=None, ident=None, method="GET", body=None, timeout=15):
    headers = {"Accept": "application/json",
               "X-Emby-Authorization": "Emby " + ", ".join('%s="%s"' % kv for kv in ident.items())}
    if token: headers["X-Emby-Token"] = token
    data = None
    if body is not None:
        headers["Content-Type"] = "application/json"
        data = json.dumps(body).encode("utf-8")
    req = urllib.request.Request(base + path, data=data, headers=headers, method=method)
    try:
        with urllib.request.urlopen(req, timeout=timeout) as r:
            raw = r.read()
            return json.loads(raw) if raw else None
    except urllib.error.HTTPError as e:
        raise RuntimeError("HTTP %s %s" % (e.code, path))
```

重试策略建议：

| 状态码 | 是否重试 |
|---|---|
| `400` / `401` / `403` / `404` | 不重试（重试也没用，先修请求或重新登录） |
| `500` | 最多重试 1 次，间隔 1–2 秒 |
| `502` / `504` | 可重试 1–2 次，指数退避 |
| 网络超时 | 可重试，但播放/上报进度类请求要避免重复副作用 |

## 7. 抓包与日志

排查顺序建议：

1. **先看请求本身**：方法、路径、查询串、请求头、body 是否符合文档（多数 400/401 都是这里错）。
2. **开启服务端调试日志**：Emby 控制台 → 设置 → 高级 → 日志，能直接看到 `HttpClient` 请求与异常栈。
3. **对比官方 Web 客户端**：浏览器开发者工具里操作同一功能，照抄它的请求（它的实现是最可靠的参考）。
4. **注意代理**：NAS/反代常改写头、剥离查询参数、限制 `Content-Length`，导致本地直连正常、走域名失败。
5. **确认功能开关**：直播电视、DLNA、转码、设备控制都可能是服务端未启用，此时接口返回 404/403 而非实现问题。

## 8. 一句话排查口诀

```text
400 → 看参数
401 → 看令牌
403 → 看权限
404 → 看 ID / 看功能开关
500 → 看服务端日志
一切正常但没数据 → 看 Policy 与 Fields
```

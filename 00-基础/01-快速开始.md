# 快速开始

> [返回总目录](../README.md) ｜ [下一篇：认证与鉴权](02-认证与鉴权.md)

本文用最短路径跑通「找到服务器 → 登录 → 拉取首页 → 取播放地址」这条链路。所有请求都以 Emby Server 的 HTTP API 为准，默认端口 `8096`。

## 1. 找到服务器地址

Emby 的默认地址形如：

| 协议 | 地址 |
|---|---|
| HTTP | `http://192.168.1.10:8096` |
| HTTPS | `https://192.168.1.10:8920`（若已启用证书） |

局域网内可以用 UDP 广播自动发现（端口 `7359`，服务端开启「允许局域网发现」时生效）：

```text
向 255.255.255.255:7359 发送:
who is EmbyServer?
```

会收到一段 JSON，包含 `Address`（服务器地址）、`Id`（服务器 ID）、`Name`（服务器名）。也可以用 `GET /System/Info/Public` 拿到公开信息（不需要令牌）：

```bash
curl "http://192.168.1.10:8096/System/Info/Public"
```

```json
{
  "ServerName": "My Emby",
  "Id": "a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6",
  "Version": "4.8.8.0",
  "OperatingSystem": "Linux",
  "LocalAddress": "http://192.168.1.10:8096"
}
```

> 拿 `Id` 很重要：后面登录、上报设备、拼图片 URL 都会用到。

## 2. 登录拿令牌

认证接口是 `POST /Users/AuthenticateByName`。请求必须带上 **客户端身份头** `X-Emby-Authorization`（此时还不带 Token）：

```bash
curl -X POST "http://192.168.1.10:8096/Users/AuthenticateByName" \
  -H 'Content-Type: application/json' \
  -H 'X-Emby-Authorization: Emby UserId="", Client="MyClient", Device="PC", DeviceId="my-device-0001", Version="1.0.0"' \
  -d '{"Username":"demo","Pw":"123456"}'
```

成功返回（节选）：

```json
{
  "User": { "Id": "8f2c...", "Name": "demo", "Policy": { "IsAdministrator": false } },
  "SessionInfo": { "Id": "e5b1...", "DeviceName": "PC" },
  "AccessToken": "b7d3f0c9a1e24f6d8b0c5a7e9f1d3b2c",
  "ServerId": "a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6"
}
```

记下三样东西：`AccessToken`、`User.Id`、`SessionInfo.Id`。后续所有请求都用这三个值。

## 3. 带上令牌请求

两种等价写法，任选其一：

```bash
# 写法 A：专用头（推荐）
-H "X-Emby-Token: b7d3f0c9a1e24f6d8b0c5a7e9f1d3b2c"

# 写法 B：完整授权头
-H 'X-Emby-Authorization: Emby UserId="8f2c...", Client="MyClient", Device="PC", DeviceId="my-device-0001", Version="1.0.0", Token="b7d3f0c9a1e24f6d8b0c5a7e9f1d3b2c"'
```

> 早期客户端还常用 `?api_key=<token>` 查询参数，虽然仍可用，但令牌会出现在日志与代理记录里，**新项目不要用**。

## 4. 拉取首页视图

```bash
curl "http://192.168.1.10:8096/Users/8f2c.../Views" \
  -H "X-Emby-Token: b7d3f0c9a1e24f6d8b0c5a7e9f1d3b2c"
```

返回 `QueryResult<BaseItemDto>`，其中每个 `Items[]` 就是一个媒体库视图（`CollectionType` 为 `movies`、`tvshows`、`music` 等）。这就是首页导航的数据源。

## 5. 取某个媒体库的内容

```bash
curl "http://192.168.1.10:8096/Users/8f2c.../Items?ParentId=<视图Id>&Recursive=true&IncludeItemTypes=Movie&SortBy=SortName&SortOrder=Ascending&Limit=40&Fields=PrimaryImageAspectRatio,ProductionYear" \
  -H "X-Emby-Token: b7d3f0c9a1e24f6d8b0c5a7e9f1d3b2c"
```

要点：

- `ParentId` 传视图（或文件夹）的 `Id`；
- `Recursive=true` 表示递归子目录；
- `IncludeItemTypes` 用逗号分隔，多个类型如 `Movie,Series`；
- `Fields` 用来补字段——**默认返回的精简对象不含 `MediaStreams`、`People` 等重字段**，列表页不要加，详情页再加。

## 6. 取播放地址

播放前先问服务端「这个条目该怎么播」：

```bash
curl -X POST "http://192.168.1.10:8096/Items/<ItemId>/PlaybackInfo?UserId=8f2c..." \
  -H "X-Emby-Token: b7d3f0c9a1e24f6d8b0c5a7e9f1d3b2c" \
  -H 'Content-Type: application/json' \
  -d '{"DeviceProfile":{"MaxStreamingBitrate":120000000,"DirectPlayProfiles":[{"Container":"mp4,mkv","Type":"Video"}]}}'
```

返回 `PlaybackInfoResponse`，关键是 `MediaSources[]` 里的：

| 字段 | 含义 |
|---|---|
| `Id` | 媒体源 ID，后续上报进度要带 |
| `DirectStreamUrl` | 可直接交给播放器的地址（直连/直转封装） |
| `TranscodingUrl` | 需要转码时使用的地址（HLS 或流式） |
| `PlaySessionId` | 播放会话 ID，上报进度、停止播放必带 |

把 `DirectStreamUrl` 或 `TranscodingUrl` 拼到服务器地址上就能播放。完整示例见 [从登录到播放](../03-实战示例/01-从登录到播放.md)。

## 7. 一张图看懂调用顺序

```text
System/Info/Public          取 ServerId、确认服务在线
        │
Users/AuthenticateByName    取 AccessToken、UserId、SessionId
        │
Users/{UserId}/Views        取首页导航（媒体库列表）
        │
Users/{UserId}/Items        取列表（分页 + 过滤 + 排序）
        │
Users/{UserId}/Items/{Id}   取详情（Fields 补全字段）
        │
Items/{Id}/PlaybackInfo     取 MediaSourceId / 播放地址 / PlaySessionId
        │
播放 DirectStreamUrl 或 TranscodingUrl
        │
Sessions/Playing → Progress → Stopped   上报进度
```

## 8. 常见坑（第一次接入必看）

1. **没有 `X-Emby-Authorization` 头**：登录接口会直接 400，报「Client 信息缺失」。
2. **`UserId` 用了用户名**：路径里的 `{UserId}` 是 `User.Id`（32 位十六进制），不是 `Name`。
3. **列表为空**：多半是 `ParentId` 传错，或没加 `Recursive=true`；先用 `/Users/{UserId}/Views` 拿到正确视图 ID。
4. **图片 404**：缺少 `tag` 参数或 `PrimaryImageTag` 为空（该条目本来就没有图）。
5. **进度不保存**：`Sessions/Playing/Progress` 的 body 里必须带 `ItemId` 和 `PlaySessionId`，且 `PositionTicks` 不能长期不更新（服务端会认为会话已失联）。
6. **时间单位**：`PositionTicks`、`RunTimeTicks` 都是 tick，**1 秒 = 10,000,000 ticks**，别当成毫秒。
